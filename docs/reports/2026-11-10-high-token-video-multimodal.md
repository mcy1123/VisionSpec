# 视频 target 5–10k 视觉 token 的多模态特性（2026-11-10）

## 1. 设置

- target：Qwen3-VL-8B，fp32，3×47GB `device_map="balanced"`；所有对比均 30/30 逐 token 无损。
- 输入：
  - **1k**：原 16 帧 384×288，480–1152 token；
  - **3k**：16 帧 2×（768×576），约 3.1k token；
  - **9k**：32 帧 2×（每帧复制 2× + 2× 分辨率），9216 token；
  - **9k-128f1x**：128 帧 1×（每帧复制 8×，384×288），9216 token（用于区分“分辨率上采样”与“帧复制”）。
- draft：OPD3e step220 或 E2E-TV 在 9k target 上训练若干 update；head 在 cuda:0，target 三卡。

## 2. token 数曲线：更多 token 反而更差

fresh30，零样本 OPD3e：

| target token | mean L | τ |
|---|---:|---:|
| 1k | 862 | **3.7841** |
| 3k | 3153 | 3.5714 |
| 9k（32f2x） | 6276 | 3.4098 |

- 1k → 3k → 9k：**τ 单调下降**（3.784 → 3.571 → 3.410）。
- 9k 训练可以部分恢复，但从未超过 1k：

| 9k E2E-TV | τ |
|---|---:|
| 5 updates | 3.4790 |
| 15 updates | 3.4725 |
| 20 updates | **3.5334** |
| 30 updates | 3.5171 |

- 3k 上训练 5 updates：3.5425，反而低于 3k 零样本 3.5714。
- **最佳高 token 结果 3.5334，仍比 1k 的 3.7841 低 0.251。**

## 3. 视觉依赖：9k 不是“更不看视觉”，而是“看了但更差”

| arm | real τ | blank τ | reliance |
|---|---:|---:|---:|
| 1k OPD3e | 3.7841 | 3.2826 | **0.5015** |
| 9k step15 | 3.4725 | 3.0750 | 0.3974 |
| 9k step20 | 3.5334 | 3.0129 | **0.5205** |

- 9k step20 的 blank 掉得更多（reliance 0.5205 > 1k 0.5015），但 real/blank 的绝对值都更低。
- 说明高 token 不是“忽略视觉”，而是 **视觉-语言融合的整体质量下降**；更多 token 增加了视觉“存在感”，却没有提高可用性。

## 4. 视频内容正确性：平均接受长度不奖励正确视频

- 1k OPD3e：real 3.7841，**mismatch 3.7841**（30/30 无损；逐行 τ 不同但均值相同）。
- 9k step15：real 3.4725，**mismatch 3.4725**（30/30 无损）。
- AR token 序列 real/mismatch 不同，说明 target 内容确实变了；但 **draft 接受长度不因视频配对正确而提高**。
- blank（黑色视频）显著更低；说明 draft 用的是“有自然视觉 token”这一泛化上下文，而不是“这段视频与问题是否匹配”。

## 5. target 自身的内容敏感性：9k 反而更低

同一问题、real vs mismatch，只看 prompt 最后一个位置的 target 分布：

| target token | KL(real‖mismatch) | hidden cos | top1 一致 |
|---|---:|---:|---:|
| 1k | **0.6187** | 0.9697 | **3/5** |
| 9k | 0.3667 | 0.9741 | **5/5** |

- 9k target 对“换成另一段视频”的 first-token 分布变化 **更小**；1k 反而更容易被视频内容改变。
- 这是 token 膨胀/重复导致的 **视觉特异性稀释**：token 多了，但有效内容没有增加。

## 6. 结论

1. **5–10k target 输入在 3×47GB fp32 上可以无损跑**（9k：30/30 lossless）。
2. **单纯增加视频 token 不会让 target/draft 更好**：1k > 3k > 9k（零样本），9k 训练最多到 3.53，仍低于 1k 的 3.78。
3. **9k 训练不是没有作用**：从 3.41 恢复到 3.53；但收益随 update 饱和，30 反而回落。
4. **多模态特性**：9k 下 target 对视频内容的 first-token 敏感性更低；draft 的接受长度对“视频是否配对正确”不敏感；blank 下降主要反映“有无自然视觉 token”，不是内容匹配。
5. 要利用 5–10k，需要 **真正新增信息（更多源帧/更高分辨率原始视频）+ 在该 token 分布上从零/长训练 draft**；复制帧和上采样不是有效信息。


## 7. 关键对照：128 帧 1×（9216 token）而不是把 16 帧上采样

同一 9216 token，构造方式不同：

| 9k 输入 | 构造 | 零样本 τ | 10-update E2E-TV τ | blank τ | reliance |
|---|---|---:|---:|---:|---:|
| 32f2x | 32 帧（每帧复制2×）+ 2× 分辨率 | 3.4098 | 3.5334（20 upd） | 3.0129 | 0.5205 |
| **128f1x** | **128 帧（每帧复制8×）+ 原始 384×288** | **3.7392** | **3.8796** | **2.8428** | **1.0367** |

- 同为 **9216 token**，128f1x 比 32f2x 零样本高 **+0.329**；训练 10 updates 后 **3.8796**，比 32f2x 最好结果（3.5334）高 **+0.346**。
- 128f1x **超过 1k 参考**（OPD3e 3.7841；同预算 1k E2E10 3.7595）：+0.095 / +0.120；但 30 条配对 bootstrap CI 仍宽（128f1x−1k E2E10：**+0.120 [−0.214,+0.561]**），单 seed，不能称显著。
- 128f1x blank **2.8428**，real **3.8796**，visual reliance **1.037**，约为 1k（0.502）的 2 倍；说明 **原生分辨率下增加帧数** 确实提高了视觉依赖与接受长度。
- 结论：**问题不是“token 数”，而是 token 的来源**。把 16 帧上采样/复制到 9k 会稀释；用原生分辨率增加时间采样（128 帧）才能让 9k token 变成有效视觉信息。

## 8. 更新后的结论

1. 5–10k target **可以**在 3×47GB fp32 上无损运行（9k/9216：30/30）。
2. **32f2x 的 9k 是负结果**：1k 3.784 > 3k 3.571 > 32f2x 9k 3.410；训练最多 3.533。
3. **128f1x 的 9k 是正结果**：零样本 3.739，训练 10 updates 3.880，blank reliance 1.04；mean 超过 1k，但 CI 宽、单 seed。
4. 多模态特性：高 token 是否有用取决于**是否保留原生视觉信息**；空间上采样会稀释内容敏感性（1k KL 0.619/top1 3/5 vs 32f2x9k KL 0.367/top1 5/5），而原生多帧提高视觉依赖。
5. 下一步：128f1x 第二 seed（运行中）、blank/mismatch 对照、以及真正更多源帧（非复制）。
