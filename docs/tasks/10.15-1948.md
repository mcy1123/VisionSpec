## 1. 研究目标和冻结对照

目标不是证明 ScienceQA 能提高大模型回答准确率，而是在**冻结同一个 Qwen3-VL-8B-Instruct Target、同一个实际图像 Draft 起点、同一个 ScienceQA 图文问题集合、同一生成 Prompt 和相同部署验证器**的条件下，判断：

> **经过正确实现的在线 OPD，能否比同预算继续 SFT 更有效地提高 b63k8 树的候选覆盖、无损接受长度，以及真实解码时间？**

只用 ScienceQA，不混合 GeoQA、LLaVA-CoT、TextVQA、MSVD 等其他训练数据。历史项目数据只用来做系统对照或排查跨数据重复，不能混成受控训练结果。

冻结三臂：

| 臂 | 身份 | 训练 | 作用 |
|---|---|---|---|
| `I0` | 已核验的 **GLANCE 图像专用 warm Draft** | 不更新 | 同起点对照 |
| `I-SFT` | 从 `I0` 继续图像 QA SFT / variable-reveal CE | 是 | 必须击败的强对照 |
| `I-OPD` | 从完全相同 `I0` 用**修复位置契约的正确在线 Full-KL OPD** | 是 | 本轮待检验目标 |

**默认首选图像 warm checkpoint**：GLANCE 已用于图像 TextVQA 公平实验的 `checkpoints/head`，必须现场检查真实存储路径、模型架构、配置、权重 SHA256 和图像融合特征兼容性。**禁止**在未验证的情况下把视频 `head_video439_aligned/step1000` 或此前 QA-SFT-120 当成图像 warm。若 `checkpoints/head` 不存在或不兼容，先列候选并核查；在起点不能被证明正确时停止训练，而不是自动换模型。

- Target：冻结 Qwen3-VL-8B-Instruct；greedy、temperature=0；独立 Target AR 是无损参考。
- 草稿框架：原始 GLANCE/DFlash block16、b63k8、budget 63 **不含 root**，保持树、验证路径和缓存机制不变。
- 精度：评测统一 fp32 Target / fp32 Head、SDPA（除非最新可靠代码对某个必要设置给出经过逐 token 验证的统一替代）；两训练臂必须使用相同 head/teacher/context 精度。低学习率下采用已验证的 fp32 master weights，不允许 bf16 参数直接接受低于半 ulp 的更新而自称模型没有学到东西。
- 训练配方采用**已经修复并门禁通过的 QA 位置契约**。在本轮不同时引入 k3、Bernoulli KL、TV、P2/P3、新树、额外视觉模块或新的超参搜索。若现有可靠实现另有明确默认语义，先审计并冻结，不默默切换 loss。

源事实参考（执行时记录上游版本及实际许可）：

- 原始数据结构与划分：`data/scienceqa/problems.json`、`pid_splits.json` 等以官方仓库实测为准。

| 角色 | 目标量（独立 QA） | 来源边界 |

### 3.3 训练数据的使用方式

ScienceQA 自带标准答案、讲解 `solution/lecture`，但投机解码训练研究中：

- `I-SFT` 使用**冻结 Target 针对当前真实图像+题目+相同 Prompt 自主生成的可见 AR 轨迹**做继续 SFT。绝对不把 gold solution 或某个 2B 历史轨迹当作 Qwen3-VL-8B 的 teacher continuation。

## 4. 阶段 C：Prompt 与 Target 可见推理长度门禁

固定一个 ScienceQA 图文 Prompt（**训练和 dev/test 相同，训练前冻结字面字符串**）：

```text
[由 Qwen3-VL processor 正确绑定的真实图片对象]
Question: {question}
Options:
(A) {choice_0}
(B) {choice_1}
...

Use the image and the question to reason through the relevant scientific evidence step by step. Explain your reasoning clearly but concisely. Finish with one line in the exact format "Answer: (X)", where X is the letter of your chosen option.
```

- 选项数为真实的 2–5 等合法数量，不补假选项；按照原始选项顺序映射 A/B/C/D/E，`answer` 不能出现在输入里。
- 不把科学题的官方 `lecture/solution`、gold 答案或历史 LLM CoT 作为 prompt 的隐含上下文。
- 本实验默认只选**图像题**；不能使用视觉占位字符串但没有像素输入的假图像样本。
- 不启用私有 `<think>` 通道，不把数据集 CoT 硬塞给 Target；使用可见推理以形成较长的生成段。

正式训练前，从 **train 内按类别固定抽 32 条**，仅做 Target-only greedy AR 的长度与图像对齐试验：

1. `max_new_tokens=512` 用于**探针**。记录 p10/p50/p90 生成长度、自然 EOS、256 截断潜在比例、512 cap 比例、是否出现真实的解释段，以及多选题答案格式。
2. 如果 `>256` 的比例超过 10%，正式主实验统一设 `max_new_tokens=512`；否则统一设 256。如 512 仍有超过 10% 被强截断，在没有看 dev/test 或 Head 收益之前允许一次预注册修订到 1024 并重新通过内存/时间门禁；否则写 `blocked_length`，不把截断样本当自然结束。
3. 如果多数问题实际少于 32 token，仍可研究 ScienceQA 短输出投机解码，但**不能声称研究的是长 CoT 加速**；先如实报告，不通过人工加长问题或从答案泄漏“推理提示”来凑 token。
4. 在 2–3 张真实图片上核验 `processor` 的 image tensor/grid、fusion hidden、cache key、position、head input 与 Target 对齐；同一题不同图片必须形成不同缓存键；错误的重复 `<image>` 占位符须清除。
5. Target greedy AR 与 SPEC 必须逐 token 同一输出，包括 EOS、bonus EOS、root EOS、max_new_tokens cap，不能只比较可见文字。

交付 `preflight/length_pilot.json`、`preflight/image_processor_binding.json` 和 `preflight/ar_lossless_gate.json`。若输入图像不能确实影响对应的融合特征，阻塞训练。

## 5. 阶段 D：正确 QA-OPD 位置契约与真实图像前向门禁

先读 GLANCE 最新 `AGENTS.md`、2026-10-15 的 `qa-tree-semantics-diagnosis` 和 `qa-contract-fix-10update` 报告，读对应补丁和测试。**优先复用已修实现，而不是另写一个未经验证的 OPD trainer。** 从视频 QA 迁移到图像时，仅允许改图像输入适配、必要的 batch/mask/position 连接，不允许顺便切换 KL 目标。

必须在**同一真实 anchor**核验：

1. `n_acc` 以 anchor 相对位置正确从当前 proposal 与当前 Target 验证计算，不得沿用上一个 anchor 的绝对索引。
2. draft logits 与 teacher logits 指向**同一个下一 token 预测位置**；拒绝位置不能晚一位，teacher 在 rejected suffix 正确条件于 draft-induced prefix。
3. accepted 段 forward KL、rejected **整个合法后缀** reverse KL（包括首拒后所有有效 offset）的 mask、EOS、padding、无效位置和权重归一均与本轮冻结 Full-KL 语义一致。
4. accepted/rejected 分组与真实在线 Target greedy verification 匹配；不要把“单路径不接受”当成“top-8/树都不接受”。
5. 训练梯度 finite 且非零，优化器真正使模型更新；fp32/master state、Adam 矩和 RNG/data cursor 支持完整恢复。
6. 包含 `n_acc=0`、部分/全部接受、不同 anchor、不同批大小、padding、block16、完整后缀、EOS/截断、图片+文本混合输入的 CPU tests。
7. 使用至少 2 张真实 ScienceQA 图片的无更新 GPU replay 和真实多轮 trace 验证 Target/student 条件、融合状态和 mask，核对独立 AR。必要时再做至少 2 次真实 optimizer.step 的 smoke，保存 SHA 与恢复验证；smoke 不算正式 300-step 训练。

**任何位置/输入/无损/优化器门禁失败，必须修好并重新通过才允许正式训练**。历史误差不可因为换数据集而忽略。不得修改原生产 tree/decode/target 核心代码；如确有必要在隔离适配层修复，保存 source snapshot 和 diff，并证明历史行为未被覆盖。

## 6. 阶段 E：训练配额与配对实验

### 6.1 冻结预算

**选择 1,200 条有效且互异的 ScienceQA 图像训练题，保证每个 seed 的正式 300 updates 覆盖每条题目一次，不重复凑数。** 两个训练臂按同一 seed 读取完全一致的 1,200 条 ID 顺序，仅允许内部策略/在线 draft 轨迹不同。

| 项 | 正式配额 |
|---|---|
| 训练 QA 池 | 官方 train 中固定 1,200 条真实图像题 |
| batch 日程 | 4 道不同 QA / update × **300 updates** = 1,200 QA exposures / arm / seed |
| 模型 | `I0` 零更新、`I-SFT`、`I-OPD` |
| Seeds | `20261013`、`20261014` 两个**配对** seed；分割 seed = 20261015 |
| Anchor | 每题最多 6 个**真实不同、有效**的 anchor，每 update 上限 24，不能复制空位置凑预算 |
| LR | 两训练臂 `3e-5`、相同 constant schedule；其他 AdamW/clip/master 配置要一致并核验 |
| Teacher / Head 精度 | 统一 fp32 Target/context；Head 两臂统一 fp32，或在资源约束下统一 bf16 Head + fp32 CPU master weights，且先过有效更新门禁 |
| 验证器 | 原始 b63k8，原始树/Target verify，EOS immediate 统一 |
| Checkpoints | 初始、30、100、200、300 updates，保存 head + optimizer + RNG + data cursor + SHA |
| 输入 Prompt | 训练前唯一冻结的 ScienceQA 可见逐步推理模板 |
| 比较主结论 | **固定 step300** 的 `OPD−SFT` 在线平均 τ 及可比真实解码耗时；step100/200 次要 |

**这两个 seed 必须从同一个 I0 开始，不能 seed2 从 seed1 的训练结果继续。** 两臂同种子逐条 QA 日程相同；训练数据、图像、题目文本、输出模板、精度、EOS、优化器规格都必须一致。不同训练方法产生的有效监督位置数与 Target 额外计算量可以不同，但必须逐步完整记账；不能因为“updates 相同”就宣称 FLOPs 相同。

### 6.2 阶段门禁（避免盲目跑满）

1. **10-update 成对 smoke**：真实训练，但主要检查有无 loss/梯度错误、真实更新、图像融合、精确续训及独立 AR/SPEC。不能凭 10 updates 的随机微小 τ 波动挑超参。
2. **正式 seed1：完整配对至 update100**，同时记录 step30/100。对现有 dev 固定子集做早期灾难退化门禁：若 OPD 相对共同 I0 的 mean τ **下降超过 0.50 token**，且 top-8 覆盖**下降超过 10 个百分点**，同时独立确认不是 EOS/截断/路径 bug，则触发预注册灾难性退化停止，两臂同点收口，不再耗 GPU；报告 stop 时点，不能说它训练了 300 steps。该门槛仅是计算止损，不是统计显著性的代用品。
3. **如未触发灾难门禁，继续 seed1 的两臂至 300**。保留全部中间结果，不能只展示最优 checkpoint。
4. **再进行 seed2 的相同实验**，不因 seed1 的正负结果临时改变 batch、学习率、输入数量或策略。如果出现不可恢复的 GPU/磁盘/许可阻塞，记录已执行数量和恢复命令，标 partial/blocked。
5. 不启动三种以上 loss、按结果修改候选树预算或加第三个数据集。用户希望检验这一固定 ScienceQA 实验，不是无限自动寻参。

**重要**：如果源于局部计算限制无法可靠进行 300 updates/arm，执行代理必须在训练开始前提交统一、可核验的资源预算修订（例如两个训练臂均缩至 120 updates、训练曝光目标同步变为 480 QA/seed），保存 `amendments.jsonl`，同时报告原始计划没有完成；**不得仅对 OPD 降低样本或步数**，也不能看到 dev 结果再调预算。已开始正式训练后不允许根据某一臂结果事后改主终点。

## 7. 阶段 F：无损评测、统计和速度口径

### 7.1 固定评测集合

- dev：官方 val 图像题中冻结 **240 个不同 QA**，供 checkpoint 开发、诊断和灾难止损；可看 dev，但不得更换样本去追结果。
- test：官方 test 图像题中冻结 **240 个不同 QA**，在模型、推理设置、主分析步骤和所有规则全部冻结后**只运行一次最终评测**。此处的 test 即“ScienceQA 官方 test 的 240 题子集”，不得冒称官方全量 test 或外部 unseen dataset。
- 如果有共图 QA，按图片簇做视频/图像组级配对 bootstrap，而不是把同一张图的多个题目或数千 token 当独立观测。

### 7.2 必须汇报的指标

对每个 seed 的 `I0 / SFT-step30/100/200/300 / OPD-step30/100/200/300` 报：

1. `mean per-image-group τ`、pooled τ、median τ、总轮数、有效输出 tokens/round、bonus/EOS/截断贡献；主数值一律来自真实在线解码，不使用离线 `L_raw` 替代。
2. 在相同正确 AR prefix/同 anchor 上的**实际** top-8 成员、rank、top8 cutoff margin、首个阻断原因（候选缺失/候选在 top8 但不在完整树/提交不一致）、`L_raw/L_tree/L_actual/tree_gap`。同一固定 anchor 与各臂自身在线 τ 分开列。
3. 按题目主题（natural/social/language science）、原始图像类型、自然 EOS 与推理长度桶统计：`1–31`、`32–63`、`64–127`、`128–255`，如正式上限≥512 再包括 `256–511`、`512+`/capped。标每桶题目数，不从极少样本得出普遍结论。
4. 所有输入的 `SPEC == independent greedy Target AR` **逐 token**无损门禁；计入 EOS 和 cap，任何失败均暂停加速结论、先查真正部署路径，不仅比较可见字符。
5. 真实计时：同一空闲 GPU、同一 fp32/SDPA/缓存/warmup 和计时策略，至少两轮不带重型 hook 的重复：`decode-only ms/token`、`prefill+decode ms/request`、端到端 image read+processor+prefill+decode、Target/Draft/tree build/verify 分项成本、显存峰值。同步 CUDA，顺序交叉运行以减少漂移。共享负载变化则标 `timing_contaminated`，不得包装为加速成果。
6. 对 `I-OPD-step300 − I-SFT-step300` 给出按独立图像簇配对的 bootstrap 95% CI（固定 2000 次和 seed），列每 seed、每图像簇正/负/相同数量，并报告 `OPD−I0`、`SFT−I0`。两 seeds 不能当作大量独立图片重复凑显著性。
7. 在独立附录可将冻结 Target 的多选题选项准确率与 ScienceQA gold `answer` 比较，但它不决定 head 优劣；无损投机解码不能提高固定 Target 的正确率。不要利用 gold 在推理中选候选或挑最好图像样本。

### 7.3 判断规则

- **继续研究条件**：OPD 相对同预算 continue-SFT 在两个配对 seed 下表现一致，有可复核的在线接受增益、实际头部候选/树覆盖解释，并在干净计时中形成真实 decode-only 或端到端延迟收益；即使成功也不能直接宣称 ACL 创新，需再研究方法机制与强基线。
- **普通负结果**：OPD 没有可靠超过 SFT，或只在离线 top-8 改善而在线 τ/时间没有改善。报告原结果，停止这套 ScienceQA 全词表 KL 配方，不自动改成 k3/TV/P2/P3 或增加训练轮次。
- **短回答问题**：若 ScienceQA 输出多数短于 32 tokens，则结论只能适用于短/中等长度图文科学问答，不冒称长推理加速。
- **不一致阻塞**：任何一臂 SPEC≠独立 Target AR，或图片路径/官方 split 复核失败，先停加速结论。不得只因可见文本相同就宣称无损。
