## 0. 研究目标、已有事实与本轮要回答的问题

### 0.1 总目标

研究冻结 Qwen3-VL-8B-Instruct 作为 target 的 GLANCE/DFlash 视频无损投机解码：在**回答 token 与目标模型独立 greedy AR 完全一致**的前提下，比较在视频问答任务上从相同 C0 起点继续 SFT 或运行 full-KL OPD，究竟谁能够使草稿头预测、实际接受长度和真实解码延迟更好。

1. 原解码器 bonus EOS 延迟停止是否污染了短答/解释式问答中的轮次和计时？修复后历史现象还能否保留？

## 3. D1：独立修复 EOS 终止边界，并真实复测

### 3.1 精确定位与最小修复

1. 用现有已保存的短答及 B 格式真实 trace，复现“提交 bonus EOS → 下一轮以 EOS 为 root”的具体情形，记录原 `start`、输出 prefix、实际 root/bonus、EOS 首次出现位置与错误多余验证轮次。
2. 在隔离代码副本/可回滚 patch 中修复，使每次提交 accepted draft tokens、target bonus 或其他路径上的 EOS 后均立即结束生成；只扫描本次新生成的 token 区间，**不要因 chat prompt 中的 `<|im_end|>` 提前停止**。
3. 覆盖以下分支：EOS 作为已接受的候选、EOS 作为 bonus、root 已 EOS、EOS 恰好在 max_new 末尾、未发生 EOS 而因长度裁剪结束、zero-accepted、首轮和末轮、不同预算、边界为空等。
4. 不改树构造策略、target logits、tokenizer 规则与接受算法；区别“合法的终止”与“额外的冗余轮次”。修复后新 `τ` 数值可能改变，不能解释为 head 能力突然提高。
5. 新增独立测试、旧/新 trace 对照、代码 diff、准确 token 门禁；必须能关闭新 patch 复现旧行为，且新 patch 不引入额外 EOS/截断 bug。

## 4. D2：保留原视频真实时间轴的 Qwen3-VL 输入适配及对照

### 4.1 原则：只改变时间语义，不偷换成新的视觉任务

已知目前取原视频 16 个等距采样帧，缩成长边384并重编码成 16帧/30fps 短片。新的 real-time 适配应尽可能保持**采样的实际帧像素、顺序、数量、空间尺寸和视频视觉 token grid 不变**，只修正进入 Qwen3-VL 的原始采帧时间信息。

- 从原视频源恢复 `frame_index`, `source_fps`, `PTS_seconds`, `duration`, `time_base`, 解码帧顺序；同一 source video 的不同 QA 共用经核验的视频帧事实。
- 对稳定 CFR 视频，优先通过当前 processor 接受的 `VideoMetadata`（真实源 fps 与真实原始 frames_indices 等）构建视频时间 token。处理 `temporal_patch_size` 两帧融合时，预期 timestamp 为相应帧时间组合；格式化通常有小数位精度，不能要求每一单帧 token 都代表完整 PTS。
- 对 VFR 视频，`frame_index/source_fps` 不一定等于真实 PTS；要么实现能把**实际 PTS**以版本兼容的方式传入 processor 的局部适配，要么明确标记该样本时间不能精确表示并排除严格时序结论；禁止伪称压缩视频的 0.533s 是真实持续时间。
- 若真实 processor 当前版本仍会对输入帧二次采样，必须明确关闭或显式抵消该重复采样，使最终视觉帧数量/像素与原缓存对得上；实际对照报告 `pixel_values_videos`, `video_grid_thw`, text/video token IDs、position IDs/M-RoPE 与 time placeholder 的差异。
- 不要仅在 user 的文字问题中补一句“视频长度 X 秒”代替真正的时间索引适配；更不能把未来正确答案或标签注入 prompt。
- 任何 fusion cache key 必须包含视频帧像素与真实时间元信息、完整 prompt、processor/version 和时间模式 `legacy/real`。**legacy 与 real context 不允许缓存混用。**

官方源码核对参考（先读运行环境中真实版本）：
- `https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_vl/processing_qwen3_vl.py`
- `https://github.com/QwenLM/Qwen3-VL/blob/main/qwen-vl-utils/src/qwen_vl_utils/vision_process.py`

### 4.2 时间戳验证门禁

至少找 3 种片长的真实视频（例如短视频、几十秒、数分钟），逐帧记录原视频时间与 processor 最终实际生成的 time markers。新标记应大体按原时轴单调增长；对 CFR 的容差按两帧时域 patch 合并与文本时间格式化分辨率定义，且不得隐藏偏离。

检查：

1. `legacy` 精确复现当前 QA run 的原 token/像素输入（完全一致，不是仅长度相同）。
2. `real` 在重复运行时稳定；同视频同问题输入一致，不同时间模式有预期时间 token 差异；视频像素特征与原采样帧对应。
3. 使用 `real` 重新生成**独立 target AR**：不能期待它与 `legacy` 输出完全相同；但三臂在 `real` 条件下的 SPEC 必须分别等于这个新 AR。
4. 监测目标模型输出长度、视频时间表述、NExT-QA 多选准确率，以及 target entropy 与 draft top-8 是否改变；不以定性个例声称时间轴修正一定提高理解准确率。

### 4.3 时间语义 A/B 复测（未训练）

在 EOS 已修复的条件下，使用同一已冻结 QA 样本与 C0/C1/C2，针对**三个数据集 B 格式完整做 `legacy_time` vs `real_time` 两条件对照**；至少报告 mean per-video τ、真实 EOS/轮次、target 输出长度和熵、top-8、SPEC=AR、有效 QA 准确率（仅 NExT MC 有明确自动计分）、wall 时延。

此处 AR 在两种时间模式下可能不同，因此比较的是**输入语义改变的整体影响**，不是同一 token reference 下纯草稿能力差异。明确分开四种解释：视频时间变化、target 输出变化、草稿输入变化、终止逻辑影响。

**训练输入规范：**如果 `real_time` adapter 门禁通过，就在 `real_time + eos_fixed` 上开展以下两臂训练；否则不得悄悄退回 legacy 而仍称“已修复时间戳”。可在独立日志说明硬阻塞并用 `legacy_time + eos_fixed` 完成注明限制的训练，但最终标签必须准确，且两臂一致。

### 5.1 训练范围：主训练选 MSVD-QA，评测覆盖三数据集

默认主训练任务是 **MSVD-QA B 格式（自然语言问答 + 1–2句可见依据）**，因为它最适合作为低复杂度视频 QA 的方法检验和后续跨数据集迁移试验。**本轮必须完成这套 QA-SFT 与 QA-OPD 对照训练**；MSRVTT/NExT 首先承担独立领域验证，不要求同时完成三套独立领域训练，除非主训练完成并有明确额外算力预算。

- 使用合法的 **MSVD-QA official train** 的实际可取得数据，按 source video ID 聚合；一个视频可以有多道 QA，但视频身份不能同时进 train/dev/confirm。
- 旧 2026-10-13 run 中 20视频/40QA、两格式的 MSVD/MSRVTT/NExT 样本均用于过方法选择与诊断，是**开发数据，绝不是 untouched test**，禁止进入 QA 训练。
- 从官方 val 尚未使用的不同视频中预先冻结 `qa_confirm`（目标每数据集约 60 视频，每视频至多2 QA；可用量不足时保留真实数量，不得借用 test 或复制同一视频凑数），**训练 checkpoint 和配置冻结之前不能读取该确认集的模型表现**。
- 如果已有官方 val 视频数不足以同时支持开发与确认，只能按实际可用合法视频调整；优先确保 MSVD 的视频级独立确认集有效，其他组至少保留旧 20 视频开发评测并标注限制。
- MSVD 训练视频不要与历史 VideoDetailCaption 训练/开发或 MSRVTT/NExT 验证视频产生可发现的同源泄漏；检查 ID、URL/源 clip、哈希，有条件采用抽帧感知哈希对高相似片段辅助审计；来源无法排除时显式标 `overlap_unknown`，不能谎称 never-seen。
- 训练、开发、确认、其他历史冻结测试候选完全分开。不得访问 official test 答案或 `results/phaseC/testset_candidates/` 来选择算法。

### 5.2 Prompt/标签/teacher 数据规则

- 完整复用 2026-10-13 的 **B 格式实际 prompt**，不能临时换成“回答更长更详细”的新模板来抬高 τ。NExT 多选保留选项且正确答案不可出现在 prompt；A 格式仅为 EOS/质量辅助。
- 冻结 target 使用同一 target 数值、同一时间戳与 EOS 输入规范，贪心生成 teacher continuation；设置与旧 B 可比的输出上限（已有 B 为 `max_new_tokens=160`），记录长答真实 EOS 情况。
- 训练视频对应多个不同 QA 时，允许 target 输出不同，但训练样本索引和暴露顺序必须严格可复现。
- SFT 应保留现有 `continue-SFT` 的原生监督定义（例如 variable-reveal/CE，需核实），但监督文本应来自**当前规范下的正确 target AR**；OPD 在相同样本日程上运行其独立 on-policy 草稿 proposal 与当前 target 条件分布蒸馏。
- 不得为构造 SFT 标签，把 gold QA 标答变相注入 target 生成；那会把“让草稿拟合 target”变成另一个任务。
- 如果 teacher 本身回答不正确或 B 的解释包含无法从视频验证的细节，保留事实/标注并如实说明质量风险；不能为改善加速指标删除“困难”样本，除非是在冻结采样规则下的可证明无效/损坏输入。

### 5.3 两个随机种子的共享训练日程

至少计划两组配对 seed：**`20261013`、`20261014`**。每个 seed 都从相同的未修改 C0 初始化，**必须分别训练 QA-SFT 和 QA-OPD 新 head**。

每个 seed 用预先冻结的训练 `video_id/question_id` 日程（同一视频顺序、同一输入、相同 train prompt、采帧、时间戳与 target）。不得出现“C1 10 条训练视频、C2 是另一批视频”却称同数据对照的情况。

**短 QA 的 anchor 数必须按真实输出预算设计。**原详细描述任务里“一条视频每 update 24 anchors”的假设不能直接套到平均仅约 37 tokens 的 MSVD B 上。默认每个 update 输入 **4 道预先列定的 QA（尽量4个不同视频），每题最多取6个真实、不同、有效的 anchor**，形成最多 24 anchors/update；不足则按真实数量记录，**不得复制短回答末轮、制造无效 anchor 或重复同一状态以凑数**。两臂必须处理同一4道 QA，策略相关的 anchor 数与位置可以不同。对每题取哪些轮次的规则在训练前冻结（例如只从实际可达非终止轮等距抽样，EOS/末轮单列），禁止按是否提升选择位置。若4题方案在 pilot 中造成硬 OOM/吞吐不可行，只能先整体冻结一份双方共同执行的调整协议，再重开正式训练；不可单独调一种方法。

OPD 的 proposal/anchor 是当前 head **策略相关**的，可以合理不同于 SFT，也可能随训练变化；不能为了强制 anchor IDs 相同而把 on-policy 算法改成固定 off-policy。**相同的是外生数据和预定计算/曝光预算，不是硬要求每个策略的内部轨迹相同。**

## 6. D4：必须实际完成 QA-SFT 与 QA-OPD 训练

### 6.1 固定训练配置（有资源适配但不做收益驱动调参）

从正式 C4 已验证的训练设置起步，而不是盲搜。默认：

| 项 | 主计划 |
|---|---|
| 起点 | C0 `head_video439_aligned/step1000`，每个方法/seed 独立重载 |
| 冻结 target | Qwen3-VL-8B-Instruct，不训练 target |
| 精度 | target/teacher/context fp32；train head bf16 + **CPU fp32 master weights**；推理评测 target/head fp32 |
| Optimizer | 复用 C4 经过核实的 AdamW 与 `repro/master_optim.py`，fp32 主权重上梯度裁剪，保存 optimizer/master/RNG 状态 |
| LR | 默认 `3e-5`，两方法一致；必要时统一修正只根据数值稳定性而不是 τ 选择 |
| 更新规模 | **每臂/每 seed 120 次有效 optimizer updates**，默认每次固定4道 QA、每题最多6个有效不同 anchor（上限24，实际可少于24）；应记录真实有效 anchors 与监督位置。不自动加步数寻找正数 |
| 阶段性 checkpoint | update 0、30、60、90、120；训练端只存可完全恢复的相应状态，不覆盖旧模型 |
| Primary evaluation | `MSVD-QA / B` 的视频级 mean τ，以及对 C0、QA-SFT 的配对改善 |
| Secondary | 三数据集 B；A 只做 EOS 敏感验证；top-8、target熵、非终止首拒、effective tokens/round、实际时延 |
| Seeds | 主计划2个配对 seed；第三seed只在预先规定的资源额度允许且不会挤掉基础对照时补做，不能只给表现好的方法增加seed |

**资源不允许一次处理一个 update 的最多 24 anchors 时**，优先通过 microbatch/gradient accumulation、teacher logits 分块/流式归约、缓存释放、CPU master offload、激活检查点或局部串行化解决；如果必须改变 updates/anchors/prompt cap，先修改预注册计划并对两臂、所有未开始的种子统一采用新预算。不允许某个方法 OOM 后悄悄减少监督而不记录；不能把 10 步探索 checkpoint 当成这次“已完成对照训练”。

前 3–5 个真实 update 是训练/显存/梯度/恢复门禁 pilot；应确认一次 `loss.backward()`、optimizer step、非零参数更新、梯度有效、权重哈希变化、学习率与累积生效。pilot 可纳入正式训练**仅当它完全使用冻结的正式配置、训练日程和 optimizer 状态并且不改变方法定义**，否则单列废弃。

### 6.2 SFT：当前正确 target AR 下的公平控制臂

- 沿用项目当前 continue-SFT 的正式损失语义（查明是否 variable-reveal、如何计算 label/reveal positions），在同一个 QA 问题及同一 target AR 数据上训练。
- 监督 mask 必须正确排除视频视觉 token、prompt 和 padding；只训练目标解码输出的合法位置，EOS 包含与否要清楚说明。
- 与 OPD 共享当前视频 QA 样本与日程，记录**实际有效监督 tokens/positions、有效视频、更新数、gradient norm、weight delta、checkpoint 时间**。
- 如果 SFT 原脚本无法支持新时间戳，独立移植而不是退回未校准的 `uncached` 特征路径。

### 6.3 OPD：不能再把旧静态序列伪装成当前 on-policy

项目历史审计发现 `opd_online_rollout` 曾同时使用“当前 head 生成 proposal/anchor”与“旧 continuation 作为 want”，而 teacher 在另一条当前 fp32 条件路径前向。新 QA 训练不得复用这一不一致结构并声称部署同轨在线训练。

必须核对 OPD 数据语义：

1. 在每个当前训练输入的 target greedy AR 上形成正确的基础上下文，或者通过可验证的真实 target 解码路径得到符合训练方案的状态；冻结 target 不变。
2. 当前 head 在当前状态提出 proposal；若声称“on-policy/online”则 accepted 长度应来自**当前 target 在真实 proposal 条件下的验证/匹配**，不能读取旧已保存答案 token 冒充当前验证。
3. 第一个 rejected 位置之前 prefix 一致；拒绝位置之后的 `draft-induced prefix` 与正确 AR prefix 不同是预期，teacher 要在对应 prefix 上计算分布，不得把两者 logits 混用。
4. 保留本项目正式实现的 full-vocabulary：accepted 位置 **forward KL**；rejected suffix **reverse KL** 按 `0.8^(k−1)` 加权；两流分别归一，有一流为空时按实际定义重归一；不能把 top-k 重归一化或随意 CE 近似叫成原 full-KL。
5. 复查 EOS/root/bonus、max length、video fused context、KV/position/mask、branch labels；训练用的线上参考必须与新 EOS/时间语义保持一致，不能让历史 `want` 不一致问题重现。
6. 记录 accepted/rejected 的有效数量及权重和、全词表 KL 分项、监督 offset 总量、target teacher forward/backward 数、额外计算耗时与真实视频曝光身份。

**公平性声明务必诚实：**即使数据顺序、更新数和 anchors/update 相同，SFT 的 reveal positions、OPD 的 accepted/rejected offsets 和额外 teacher 计算也可能不同。除了 matched-exposure/updating 比较，还要呈现训练 compute/监督预算曲线；不能强行声称所有维度完全配平。若 teacher 计算差异很大，至少报告相同训练计算预算下的性能插值或一个预先冻结的小型算力对照；不能只拿“相同步数”证明 loss 因果更优。

### 6.4 完整训练、精确续训和失败收口

- 在同一配对 seed 下，交错或顺序训练 SFT 与 OPD 均可，但 GPU 背景条件与数据固定，记录顺序；不要将一种方法的结果用来调整另一方法的训练策略。
- 训练日志每步必须含样本 ID、真实 anchor、监督计数、loss 分量、梯度、lr、master weights 状态、显存/时间。保存能**精确恢复**的模型、fp32 master/Adam moments、schedule、RNG、数据游标；至少在一个非最终 checkpoint 做恢复→继续2步与不断训一致性门禁。
- checkpoint 的实际存在、权重位移和完整训练日志是“完成训练”的必要条件，创建空文件夹或伪造 step120 不能算完成。
- 只有 NaN/Inf、持续有意义的数值错误、违反无损门禁、资源/安全硬阻塞才停止该 arm；“validation 没涨”不是随意停止、私调超参或只留下正向 seed 的理由。
- 如果实际只能完成1个配对 seed，必须输出其结果并明确“单种子不足以确定方法优越性”；但正常可用资源下应按冻结计划继续第2个 seed，不能只因为首轮效果差就不做。

## 7. D5：训练期间开发评测和 checkpoint 选择

训练每隔约 30 updates 做少量固定 `MSVD-QA B` 开发评测，避免每个更新都展开完整三数据集无损解码。

- 同一个 seed 下所有 checkpoint 用相同一批**冻结开发视频**；更新0/30/60/90/120均记录，不覆盖模型。
- checkpoint 选择规则**训练前冻结**：每个 arm 在固定 MSVD-QA 开发视频上独立选择 mean per-video τ 最大的一档；并列时选更早 update。不要因为某个 OPD checkpoint 没涨，就事后用另一题型/另一指标选点。记录所选 checkpoint 与最后 step120 两套结果。
- 仅用于选择 checkpoint 的验证集不能再作为独立、无偏的最终方法证明。后续 final confirmation 必须使用没看过结果的 `qa_confirm` 视频。旧 20 视频开发结果也保留，以便与迁移评测历史口径对照。
- 开发评测在同一输入上 C0、SFT、OPD 都做 SPEC==独立 target AR 的逐 token 门禁；出现失败应停下并定位，而不是将失败的高 τ 作为最好 checkpoint。

## 8. D6：正式三数据集评测，必须真的得到对比结果

### 8.1 模型矩阵

**必须至少完成：**

1. C0 原始 aligned 起点；
2. 历史 C1/C2（不训练，供“跨任务迁移 vs 领域内训练”对照，优先复用 D1/D2 相同输入下结果）；
3. `QA-SFT(seed1)`、`QA-OPD(seed1)`；
4. `QA-SFT(seed2)`、`QA-OPD(seed2)`；
5. 各 arm 完整最终 step 与预注册选择 checkpoint 的区别。

如果资源受限，优先次序是：**至少配对训练1个seed并完整评测 → 再配对训练第2个seed → 再增加确认集视频和高重复计时**；不能反过来只做上百条现有模型评测却没有训练结果。

### 8.2 数据矩阵

- **主实验：**`MSVD-QA/B`，相同 QA 数据体系内新训练模型的对照；
- **跨域验证：**`MSRVTT-QA/B` 和 `NExT-QA 五选一/B`，训练不接触这些验证视频；
- **EOS/格式辅助：**三个数据集的 A 格式，至少保留现有 20 视频全集，A 的短答 τ 不能作为论文主要速度证据；
- **独立确认：**只在模型/设置冻结后打开每数据集预先划分的 `qa_confirm` 视频（若可用），避免一再用已做方法选择的20视频当最终 test。

每组输入先通过 processor/hash、时间戳/视频帧、与 target AR 一致性 smoke（至少 2–3 视频）；再完整跑到目标样本数。不能因为某组开始为负就跳过剩余任务。checkpoint/hash 在评测前后核对无变化。

### 8.3 主指标与配对统计

每个数据集和格式输出：

| 指标 | 要求 |
|---|---|
| mean per-video τ | 以历史 `accepted+1` 定义单列，不与 effective 混合；逐视频先聚合，再平均 |
| 有效接受与轮次 | `effective_output_tokens/round`、accepted draft tokens、bonus/root、terminal clipping、非终止轮接受长度、EOS多余轮数 |
| 候选能力 | 部署真实 GPU top-8、固定共同 anchor 上的 target token 覆盖、首拒分类、token rank；不用不同 arm 自己的在线 round 混做严格位置因果 |
| target 难度 | 正确 AR 下 target entropy/margin、首个答案 token 与排 EOS 的统计、回答长度、轮数 |
| 主效应 | `QA-OPD − QA-SFT`，并列出 `QA-OPD − C0`、`QA-SFT − C0`，逐数据集和每个 seed |
| 配对区间 | 同一视频的 QA 聚合后视频级 bootstrap（如 2000/5000 次固定seed）；相同训练seed成对报告，再汇总 seed 差异；不能把 token 当独立样本 |
| 真实速度 | 相同配置下 `decode-only ms/token`、`model wall ms/request`、`wall ms/token`、构树、draft、verify 成本；如果可行加全流程视频读取→回答端到端 |
| 质量 | SPEC=AR；NExT QA 选项准确率；MSVD/MSRVTT 只有经过验证的标准化/语义评分才能称答案质量，不把字面 EM 当官方语义精度 |

同一视频多个 QA 的相关性、seed 方差与不同数据集可能的来源重叠必须说明。主比较预先设为 **MSVD-QA B、独立确认视频上的 QA-OPD vs QA-SFT**；其他两个 B 是跨域的次要比较。多数据集/多版本探索不通过挑选最有利置信区间决定结论。

**特别警惕：**两种方法冻结同一 target 且满足无损，目标输出/准确率必然相同（同一时间语义/输入下），故不能拿 NExT准确率变化归因 OPD。`τ` 不等于 wall-clock 加速；如果更高的 τ 伴随构树/teacher开销上升，应如实报负面结果。

### 8.4 计时纪律

- 全部主时延比较使用相同 GPU、dtype、attention backend、batch/输入、线程环境；两臂按冻结的交错/反向顺序跑，以减轻时段漂移。计时前各有独立 warmup，正式样本不因执行顺序被删除。
- 至少两次不带重型 hooks 的独立干净重复；必要时三次。记录 GPU synchronize、当前系统负载、peak memory 与其他进程；数据/processor/CPU↔GPU 传输是否计入分别说清楚。
- 对在训练中途因外来任务进入 GPU 或明显负载扰动的批次，记录中断并可断点恢复；不能混拼被污染的计时为“显著加速”。token 无损门禁与时延可信性分别判断。
- `decode-only` 当前历史窗口不含首次 draft/build；请保留该口径便于可比，同时额外报包含首轮的 `model wall`，条件允许才测完整端到端。

## 9. 结果是否证明 OPD 更优：预先冻结的判断原则

**A. 认为“初步支持 QA-OPD 有优势”的条件：**

- 独立确认视频上，至少两个配对训练 seed 的 `QA-OPD − QA-SFT` 在主 MSVD B 都有正向倾向，且 `QA-OPD − C0` 也不劣；
- 与随机波动相比有足够明确的效应和区间，最好同时有可比模型 wall 或 decode-only 的真实改善；
- GPU/数值/数据/准确 token 门禁完全通过，没有通过截短答案、增加不合理循环轮次或改变输入文本获得虚假提升。

**B. 认为“不支持当前 OPD 配方额外有效”的条件：**

- 正确修复 EOS/时间语义、至少一组完成的真实 QA 训练与独立确认评测后，`QA-OPD − QA-SFT` 效应接近0或方向不稳定、区间跨零，或真实 wall 没有改善；
- 即使 SFT、OPD 都优于 C0，也可能是数据领域适配的普遍收益，**不是 OPD 专属贡献**。

**C. 中间态：**仅一个 seed、有轻微 τ 正数、仅旧20视频为正、新确认集不稳定、计时受外来负载影响等，必须写“证据不足”，不能根据主观期待选结论。

可以附加内部实用价值阈值作为参考（例如 `+0.10 τ` 或 `model wall` 至少约 3% 改善），**它们不是统计显著性或 ACL 录用标准**，也不可以仅靠阈值就认定新方法有效。

禁止下一轮自动恢复大规模 OPD 超参搜索，尤其不得在验证集反复挑数据、调整 loss 权重，直到最终结果转正。若对照负面，也必须完整交付，作为后续方法研究的可靠结论。

## 11. 训练完成定义、不可接受的“伪完成”与自动执行顺序

### 11.1 什么才算本任务完成？

- EOS 修复及对应原始与修复后真实无损评测已经执行，门禁结果和主要数字有文件证据；
- 时间戳 adapter 和 `legacy/real` 实测已执行，帧/时间映射可审计，准确记录其语义；
